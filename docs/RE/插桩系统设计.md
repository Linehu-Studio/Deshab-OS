## 1. 概述

### 1.1 设计目标

为 Deshab 内核及各子系统建立统一的插桩基础设施，解决以下问题：

| 问题 | 现状 | 插桩方案 |
|------|------|----------|
| 无运行时日志过滤 | 所有 `log_info/warn/error` 无条件输出到串口 | `INSTR_LOG` 带级别+模块过滤 |
| 无结构化事件记录 | 仅线性串口输出，无法事后回溯 | `INSTR_PROBE` 环形探测缓冲 |
| 无轻量级统计 | 热路径缺乏量化数据 | `INSTR_STAT` 计数器+周期摘要 |
| 无跨模块统一接口 | UTSM/DKM/DSK 各用不同日志接口 | 统一 `INSTR_*` 宏体系 |
| 无配置控制 | 插桩代码无法运行时开关 | FUCK `[debug]` 配置段 |

### 1.2 设计原则

1. **零开销禁用**: `g_instr_enabled=0` 时所有宏展开为空操作，不引入任何分支或内存访问
2. **热路径安全**: `STAT_INC` 仅 `if(enabled) count++`，一条条件分支；`PROBE` 仅条件写入
3. **统一接口**: 所有 UTSM 模块使用 `INSTR_*` 宏；DKM 驱动使用 `DKM_*` 宏
4. **配置驱动**: 通过 FUCK `[debug]` 段控制开关与粒度，无需重编译
5. **标签编码**: 4 字符 ASCII 编码为 u32，避免字符串比较开销

## 2. FUCK `[debug]` 配置说明

### 2.1 配置段

```ini
[debug]
# 全局插桩开关 (0=禁用，零开销; 1=启用所有 INSTR_* 宏)
enabled=0

# 日志级别阈值
#   0=TRACE, 1=DEBUG, 2=INFO, 3=WARN, 4=ERROR, 5=SILENT
#   仅 >= log_level 的 INSTR_LOG 消息才输出
log_level=2

# 探测缓冲开关 (0=禁用; 1=启用 INSTR_PROBE 写入环形缓冲)
probe_enable=0

# 探测缓冲容量 (条目数，每条 40 字节)
#   默认 4096 条 ≈ 160KB
probe_capacity=4096

# 统计摘要间隔 (每 N 次增量输出一次摘要)
stat_summary_interval=256

# 模块级过滤: 1=启用该模块的 TRACE/DEBUG 级别日志
utsm_trace=0
vmm_trace=0
dkm_trace=0
dsk_trace=0
block_trace=0
net_trace=0
input_trace=0
```

### 2.2 启用方式

**调试启动性能**:
```ini
[debug]
enabled=1
log_level=1
# 启动时观察各阶段耗时
```

**调试 VMM VM-Exit**:
```ini
[debug]
enabled=1
log_level=1
probe_enable=1
vmm_trace=1
```

**调试 AHCI DMA**:
```ini
[debug]
enabled=1
log_level=1
dkm_trace=1
block_trace=1
```

## 3. 宏系统设计

### 3.1 INSTR_LOG — 带级别和模块过滤的日志

```c
INSTR_LOG(level, mod_flag, msg)
```

- `level`: `INSTR_LOG_TRACE(0)` / `DEBUG(1)` / `INFO(2)` / `WARN(3)` / `ERROR(4)` / `SILENT(5)`
- `mod_flag`: `INSTR_F_xxx` 模块标志位，或 `0` 表示不过滤
- `msg`: 常量字符串

**过滤逻辑**:
```
g_instr_enabled && level >= g_instr_log_level && (mod_flag==0 || mod_flag & g_instr_module_flags)
```

### 3.2 INSTR_STAT — 轻量级计数器

```c
INSTR_STAT_DECL(name)    // 声明: static u64 name_count + name_last_ts
INSTR_STAT_INC(name)     // 自增: if(enabled) name_count++
INSTR_STAT_SUMMARY(name) // 摘要: 达到间隔时输出并重置
```

**设计要点**:
- `STAT_INC` 仅 `if(enabled) count++`，一条条件分支，极轻量
- `STAT_SUMMARY` 在 `count >= stat_interval` 时输出，自动重置
- 适合热路径：VM-Exit 分发、IRQ handler、网络收发

### 3.3 INSTR_PROBE — 环形探测缓冲

```c
INSTR_PROBE(tag, a0, a1, a2, a3)
```

- `tag`: 标签常量 `INSTR_TAG_xxx`，4 字符 ASCII 编码为 u32
- `a0-a3`: 4 个 u64 参数，语义由标签定义

**探测条目结构** (40 字节/条):
```c
typedef struct probe_entry {
    u32 tag;        // 4字符ASCII标签
    u32 tick;       // 低32位TSC（~2s溢出@2GHz，足够诊断）
    u64 args[4];    // 4个u64参数
} probe_entry;
```

**环形缓冲行为**:
- 容量由 `probe_capacity` 控制（默认 4096 条）
- 写入时 head 指针推进，满时覆盖最旧记录
- 通过 `probe_read(n, out)` 读取最近 N 条
- 通过 shell `$probe` 命令读取（Phase 4 实现）

### 3.4 INSTR_TS — 时间戳标注

```c
INSTR_TS_DECL(name)       // 声明: static u64 name_ts
INSTR_TS_BEGIN(name)      // 记录: name_ts = instr_rdtsc()
INSTR_TS_END(name, label) // 输出: "[TS] label elapsed_ms=0x..."
```

**设计要点**:
- 使用 `instr_tsc_per_ms`（独立于 serial.c 的 TSC 校准）
- 仅在 `g_instr_enabled` 时输出
- 适合启动阶段耗时测量

### 4.1 编码规则

4 字符 ASCII 大端序编码为 u32：

```
'B'(0x42) 'O'(0x4F) 'O'(0x4F) 'T'(0x54) → 0x424F4F54
```

4. 避免与已有标签冲突

| **mouseInit** | 计数器 | IRQ12 包统计（已有日志） |

## 6. 探测缓冲系统设计

### 6.1 数据结构

```
probe_entry (40 bytes):
┌──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
│ tag  │ tick │      args[0]    │    args[1]    │    args[2]    │    args[3]    │
│ u32  │ u32  │      u64        │    u64        │    u64        │    u64        │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘
```

### 6.2 环形缓冲管理

```
g_probe_buf[0..cap-1]  ← arena 分配的连续内存
g_probe_head           ← 下一条写入位置（单调递增）
g_probe_count          ← 已写入总条目数

写入: idx = head % cap; buf[idx] = entry; head++; count++;
读取: 从 (head - n) 到 head，按时间顺序
```

### 6.3 读取接口

```c
int  probe_read(u32 n, probe_entry *out);  // 读取最近 N 条
u32  probe_count(void);                     // 已写入总条目数
u32  probe_capacity(void);                  // 缓冲容量
```

### 6.4 Shell 命令

```
probe            — 显示最近 16 条探测记录
probe 64         — 显示最近 64 条探测记录
probe stat       — 显示探测缓冲统计信息
probe tags       — 显示所有已知标签
```

**实现方式**: UTSM 在 `dsk_fill_boot_context()` 中通过 `reserved[6]` 传递 `probe_info` 结构体指针，
shell 从中读取探测缓冲地址并直接访问共享内存。`probe_info` 结构定义在 `dsk.h` 中：

```c
typedef struct probe_info {
    u32 magic;              /* PROBE_INFO_MAGIC = 0x50524F42 ("PRFB") */
    u32 version;            /* ABI 版本，当前 1 */
    u64 probe_buf_addr;     /* probe_entry 缓冲基地址 */
    u32 probe_cap;          /* 缓冲容量（条目数） */
    u32 probe_head;         /* 当前写入位置 */
    u32 probe_count;        /* 已写入总条目数 */
    u32 probe_dropped;      /* 覆盖条目数 */
    u32 instr_enabled;      /* 插桩开关快照 */
    u32 instr_probe_enable; /* 探测开关快照 */
    u64 reserved[4];
} probe_info;
```

## 7. 零开销设计说明

### 7.1 禁用时展开

当 `g_instr_enabled=0`（默认配置）时：

```c
INSTR_LOG(level, mod_flag, msg)
→ if (0 && ...) { ... }   // 编译器优化为空操作

INSTR_STAT_INC(name)
→ if (0) { name_count++; } // 编译器优化为空操作

INSTR_PROBE(tag, a0, a1, a2, a3)
→ if (0 && 0) probe_write(...)  // 编译器优化为空操作

INSTR_TS_BEGIN(name) / INSTR_TS_END(name, label)
→ name_ts = rdtsc();          // 写入 static 变量（可优化掉）
→ if (0) { ... }              // 编译器优化为空操作
```

### 7.2 热路径分析

**vmexit_dispatch** (每秒可能数千次):
- `INSTR_STAT_INC(vmexit_total)`: `if(enabled) count++` → 一条条件自增
- 所有 STAT_INC 合计: 1 条条件分支 + 1 条自增
- 无 PROBE 写入（仅在 `probe_enable=1` 时触发）
- 无 LOG 输出（仅在 `log_level <= DEBUG` 时触发）

**idt_handler** (每次中断/异常):
- `INSTR_STAT_INC(pic_irq_total)`: 一条条件自增
- `INSTR_PROBE(EXCP)`: 仅 CPU 异常时触发（极低频）
